# سياسة النسخ الاحتياطي والأمان

## 1. ما يُرفع إلى GitHub
GitHub مخصص **للكود والمخططات (migrations/schema) فقط**.

لا يُرفع إلى المستودع أبداً:
- بيانات المستخدمين أو المتبرعين أو الموظفين
- نسخ قواعد البيانات (`.sql`, `.dump`, `.sql.gz`)
- ملفات التخزين والمرفقات
- كلمات المرور أو المفاتيح أو ملفات `.env`

## 2. لماذا أُوقف النسخ الخام إلى GitHub
كانت هناك وظيفة تصدّر جداول قاعدة البيانات كملف JSON إلى مستودع GitHub. هذا يعني وجود بيانات شخصية بصيغة نصية واضحة داخل نظام إدارة كود، مع سجل تاريخي دائم لا يمكن حذفه بسهولة. لذلك أُلغيت الوظيفة بالكامل.

## 3. النموذج الآمن المعتمد
1. توليد نسخة من قاعدة البيانات عبر `pg_dump` في بيئة تنفيذ موثوقة.
2. **تشفير النسخة قبل الرفع** باستخدام GPG (symmetric, AES256) وعبارة سرية تُحفظ في مدير أسرار.
3. رفع الملف المشفّر فقط إلى تخزين خارجي متوافق مع S3 (AWS S3 أو Cloudflare R2) في سلة خاصة مع تفعيل الإصدارات (versioning) ومنع الوصول العام.
4. عدم حفظ أي نسخة كـ GitHub artifact ولا داخل المستودع.

## 4. سياسة الاحتفاظ
- نسخ يومية: تُحفظ 14 يوماً
- نسخ أسبوعية: تُحفظ 8 أسابيع
- نسخ شهرية: تُحفظ 12 شهراً
- تُطبق عبر Lifecycle Rules في السلة، لا يدوياً.

## 5. اختبار الاستعادة
- اختبار استعادة كامل **كل شهر** على قاعدة بيانات اختبارية منفصلة.
- تسجيل: تاريخ الاختبار، حجم النسخة، مدة الاستعادة، النتيجة.
- نسخة لم تُختبر استعادتها = نسخة غير موجودة.

## 6. الأسرار المطلوبة
تُضاف في GitHub Actions Secrets أو مدير الأسرار، ولا تُكتب في الكود:
`DATABASE_URL`, `BACKUP_S3_ENDPOINT`, `BACKUP_S3_BUCKET`, `BACKUP_S3_REGION`, `BACKUP_S3_ACCESS_KEY_ID`, `BACKUP_S3_SECRET_ACCESS_KEY`, `BACKUP_ENCRYPTION_PASSPHRASE`.
